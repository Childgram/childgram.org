# Выпуски Android и сайт Childgram

Постоянный адрес приложения: **https://update.childgram.org/android.json**.
Публичный сайт: **https://childgram.org**. APK хранятся в релизах
[Childgram/cg-android](https://github.com/Childgram/cg-android/releases).

## Репозитории и публикация

Android — самостоятельный GitHub-форк `DrKLO/Telegram` с исходной историей.
Его Pages обслуживает домен обновлений. Верхний локальный репозиторий хранит
общие документы, бренд и `site/`; отдельный удалённый репозиторий для него
ещё не создан. Предлагаемое имя — `Childgram/childgram.org`.
Его Pages будет обслуживать основной сайт. Один сайт Pages имеет один
настроенный custom domain, поэтому два репозитория обслуживают два адреса.
Между репозиториями не нужен токен записи: сайт читает публичный JSON.

В Android есть два workflow:

1. **Prepare Android release draft** — ручной запуск на `master`.
   Версия и code берутся из `gradle.properties`, описание — из
   `dev/release-notes.md`. Docker собирает подписанный ARM64 APK. Проверяется
   пакет `org.childgram`, отсутствие debug-флага и закреплённый сертификат.
   В GitHub создаётся черновик с APK, JSON, SHA-256 и отпечатком сертификата.
   В описании есть ссылка на точный исходный коммит.
2. **Publish Android update feed** — после публикации, редактирования, удаления
   или снятия релиза; также можно запустить вручную. Выбирается наибольший
   опубликованный code; черновики исключены. Опубликованные alpha/prerelease
   входят в эту общую ленту. Метаданные сверяются с реальными именем, размером
   и SHA-256 GitHub-артефакта. Несогласованные данные останавливают deployment.

В верхнем репозитории **Publish Childgram website** публикует только экспорт
из `site/` и общий SVG-логотип. Документы, Android-исходники и `.local` с ключами
в содержимое сайта не попадают. При недоступном JSON или отключённом JavaScript
остаётся ссылка на страницу релизов; при доступном — прямая ссылка на APK.

## Первый запуск GitHub Actions

Это подготовленные локальные изменения. Коммиты, push, настройка Pages,
загрузка секретов и DNS пока не выполнены.

После отдельного разрешения на публикацию:

1. Опубликовать подготовленные изменения Android в основной ветке форка,
   сохранив upstream-историю. Создать отдельный публичный репозиторий для
   верхнего каталога и опубликовать его `main`.
2. В Android создать environment `release` с ограничением на `master` и ручным
   подтверждением запуска. Перенести существующие реквизиты в четыре secrets:
   `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `CHILDGRAM_RELEASE_KEY_BASE64`,
   `CHILDGRAM_RELEASE_KEY_PASSWORD`. Выпускной ключ не регенерировать;
   сохранять отдельную резервную копию. Сам ключ передаётся только в secrets
   GitHub и временный runner, не в Git или релизные assets.
   В настройках форка разрешить выполнение GitHub Actions, если оно выключено.
3. В обоих репозиториях включить Pages → Source: **GitHub Actions**.
   Custom domain Android: `update.childgram.org`; верхнего репозитория:
   `childgram.org`. Файлы CNAME в экспорте документируют назначение сайта,
   но при публикации через Actions не заменяют настройку custom domain.
4. Настроить `github-pages`: Android-события релиза должны иметь возможность
   deployment с тегов `v*`, ручные запуски — с `master`; сайт — с `main`.
5. Проверить владение `childgram.org` в организации GitHub через предложенный
   GitHub TXT. Затем изменить только нужные DNS-записи у Porkbun.
6. После настройки Pages запустить вручную **Publish Android update feed**
   и **Publish Childgram website**. Это также повторяет публикацию, если
   автоматический запуск при первом push произошёл до настройки Pages.

| Имя | Тип | Значение |
| --- | --- | --- |
| `update` | CNAME | `childgram.github.io` |
| `@` | A | `185.199.108.153` |
| `@` | A | `185.199.109.153` |
| `@` | A | `185.199.110.153` |
| `@` | A | `185.199.111.153` |

У существующего имени `update` не должно одновременно оставаться другого CNAME
или A. Почтовые MX/TXT и остальные поддомены не менять. `www` необязателен;
при необходимости его CNAME также указывает на `childgram.github.io`.
Домен сначала закрепляется в Pages, затем переключается DNS.
После выдачи сертификатов включить **Enforce HTTPS** и проверить оба HTTPS-адреса.
На 3 октября 2026 года домены отвечали парковкой Porkbun, а Pages в Android
был выключен. Перед изменением DNS сохранить текущие записи и TTL для отката.

Проверка после настройки: HTTP 200 и валидный JSON на постоянном адресе,
HTTPS обоих доменов, корректные CORS-заголовки для чтения JSON с `childgram.org`,
ссылка на существующий APK и совпадение его хеша. Затем проверить на устройстве
реальное предложение более высокого code, загрузку, системную установку
поверх старой версии и сохранение данных.

Откат сайта/ленты — повторный deployment предыдущего успешного workflow или
исправление публикации и повторный запуск ленты. Уже установленный более новый
APK сам не откатится: для исправления нужен следующий code. При отказе от Pages
сначала убрать/восстановить его DNS-записи, затем освобождать custom domain.
Секреты можно удалить из environment; отключение workflow остановит новые сборки.

## Как выпускаем следующую версию

1. Увеличить `CHILDGRAM_VERSION_CODE`, изменить имя версии и release notes.
   Code — целое число; `alpha.10` сравнивается по code, а не как текст с `alpha.9`.
2. Собрать, установить и проверить APK локально, выполнить ручные сценарии,
   перечисленные в [подготовке релиза](release.md). Сделать точный исходный коммит.
3. Запустить **Prepare Android release draft**. Скачивать APK для ручной проверки
   можно из авторизованной страницы черновика. Черновик в приложении не появляется.
4. После проверки нажать **Publish release** в GitHub. Дождаться успешной публикации
   ленты; приложение увидит обновление при очередной проверке или по кнопке в настройках.

Если создание черновика оборвалось после появления записи, сначала проверить
его assets и удалить только этот незавершённый черновик/неиспользованный тег
либо выбрать следующую версию. Не заменять APK уже выпущенной версии и не
переназначать публичные теги. После правки release notes в GitHub JSON-чейнджлог
сам не меняется: он закреплён в `android.json`, собранном вместе с APK.

## Проверка до первого публичного выпуска

Лента без релизов: `{"schema_version":1,"available":false}`. Она уже пригодна
для публикации; приложение корректно сообщает об отсутствии обновлений.
Автономные тесты проверяют выбор версии, исключение черновиков, неполные assets,
дубли code, несовпадение хеша и небезопасные ссылки.

Проверки на устройстве используют установленный подписанный APK как локальный
образец. Они не требуют фиктивного релиза. Для ручного осмотра локального
набора assets есть `dev/release.py package --local`: такой JSON явно помечен
`local_fixture: true` и серверный генератор откажется публиковать его в ленту.
Это проверяет логику и путь установки; настоящая загрузка из GitHub через
постоянный домен проверяется только после подключения инфраструктуры.

Официальные инструкции: [custom domains](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site),
[Pages workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages),
[release events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#release).
